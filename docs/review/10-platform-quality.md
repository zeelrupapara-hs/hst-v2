# Platform quality review

Scope: cmd/, app/, config/, pkg/{db,logger,redis,nats,cache,http,errors,journal,influxdb} in all four modules; hst-server/migrations (76 files) vs hst-server/model; hst-server/seed; all five Makefiles; cross-module `pkg/` diff; `go build`, `go vet`, `gofmt -l` per module; function/file size and doc-comment pass over hst-server/internal/server/v1 and hst-core/handler. 61 files read fully, ~6,300 lines, plus AST scans over all 57,899 non-test Go lines.

## Summary
Plumbing is healthy: every module builds and vets clean, boot and shutdown are ordered correctly and symmetric, config refuses malformed env values, and the four `pkg/` copies have barely drifted (comments only, plus one intentional `Migrate` difference). The real weaknesses are structural: one HTTP mapping bug turns a 503 into a 500, `pkg/journal` publishes to NATS inside an open transaction, two error vocabularies coexist in `pkg/http` and `pkg/errors`, and there is not a single `_test.go` in 58k lines. For a junior the biggest costs are 51 functions over 80 lines (three over 200), 300 multi-line comments against a one-line house rule, ~270 exported identifiers without a doc line, and dead leftovers (gRPC/Postgres config in hst-quote and hst-news, an unused `repository` package in hst-quote, a model field for a dropped column). Readability verdict: navigable with a map, but the map does not exist yet (see Onboarding guide gaps).

## Flow traces

**Boot, hst-server** (app/app.go:38-173): config.NewConfig:40 → logger:47 → Postgres:63 → `database.Migrate()` (schema only):77 → NATS:83 → Redis:99 → OAuth2:114 → seed.Seed:126 (groups → manager → symbols → group symbols → routing → leverages, seed.go:24-47) → `server.NewServer`:135 → `srv.Run()` in goroutine:143 (WorkerStatus.Start → Mailer.Start → RegisterRoutes → Listen, server.go:91-113). Shutdown on SIGINT/SIGTERM:154: `srv.Shutdown` (WorkerStatus.Stop → Mailer.Stop → Hub.Shutdown → History.Close → `ShutdownWithTimeout`, server.go:116-128) → wait for Listen:164 → defers unwind oauth.Close → redis → nats.Drain → pool.Close → log.Sync/Close. Verdict: OK; gap = no readiness/drain step and no NATS in health (#8).

**Boot, hst-core / hst-quote / hst-news** (app/app.go): config → logger → [Postgres, core only] → NATS → Redis → [Influx + EnsureRetention, quote only] → health probes `Start` → `handler.New` → `h.Start(ctx)` (core: StartMarket load → Workers.Start → RecoverDealingRequests → background goroutines via `h.Go` → `subscribe()` last, handler.go:114-139) → `probes.Ready()`. Shutdown: `probes.Draining()` → sleep `DrainWait` → defers: `h.Stop` (unsubscribe → cancel → Workers.Stop → wg.Wait, idempotent via `once`, handler.go:143-159) → probes.Stop → redis → nats → [db] → log. Verdict: OK, matches the skill's Start/Stop contract.

**Config validation**: every `getEnvAs*` records malformed values into package-level `badEnv`; `validate()` joins them (server:406-408, core:206, quote:265, news:198). Server additionally checks JWT key, refresh TTLs, trusted proxies, TLS pair, cache bounds, argon2 bounds; quote checks service token, instance index, influx token; news checks token and index; core checks nothing beyond parse errors. Verdict: gap at pepper (#5), password escaping (#4), dead fields (#6, #9).

**Error vocabulary → HTTP**: handler returns `errs.ErrX` → `s.App.HttpResponseX(c, err)` → `fail()` writes `{success:false, code, error:<pkg/http label>, message:err.Error()}` (response.go:214-220). Unmapped statuses go through `HttpResponseStatus` (response.go:125). Verdict: gap at step 3 for 503/429/401 (#1); two label sets (#3).

**Journal entry**: `Journal.Entry` → Begin → INSERT RETURNING → `publishMsg` (NATS `SubjectJournal(login)` + Flush) → Commit (journal.go:29-67). Verdict: gap at step 4, publish before commit (#2).

**Migration → model**: 76 files, all epoch-millis named, every `.up.sql` has a `.down.sql` (checked by script); 39 tables, 15 structs with `TableName()`. Column sets match except `accounts.currency_digits` (#11) and ALTER-appended symbol columns out of struct order (#12). Types: SMALLINT/INTEGER columns map to `int32`/typed enums consistently; no narrowing mismatches found.

**pkg/ drift**: `diff -r` across the six module pairs shows comment-only drift in logger/rotate, `Migrate` present in server+quote only, and a deliberately larger `pkg/errors` in server (#30). `go.mod`: all four on go 1.25.0, pgx v5.10.0, nats.go v1.52.0, go-redis v9.21.0, zap v1.28.0, influx v2.14.0, no version drift.

**Tooling output**: `go build ./...` exit 0 ×4; `go vet ./...` exit 0 ×4; `gofmt -l`: hst-server `model/mailtemplate.go`; hst-core none; hst-quote `config/config.go`, `internal/provider/fixquotes/connector.go`, `model/datafeed.go`; hst-news none.

## Onboarding guide gaps
What a junior needs written down that is not in `CONTRIBUTION.md`, `docs/`, or the module READMEs today:
1. A repo map: four modules, no shared module, `pkg/` is copied; which copy is canonical and how to sync (there is no tool, see #30).
2. Local bring-up end to end: brew infra → `make migrate-up` in hst-server (the binary does not migrate) → `make gen-keys` → `.env` from `.env.example` (which is incomplete, #27) → root `make dev`; hst-news is missing from root `make dev` (#25).
3. "Where does X go": new HTTP endpoint = handler file in `internal/server/v1/{admin,trader}` + route line in `admin/routes.go` / `trader/routes.go` + swagger block + rights bit; new engine command = entry in `hst-core/handler/nats.go` `commands` table + subject/queue constants in `model/subjects.go` on both sides; new feed type = `provider.ModuleType` + connector package + the two switches in `hst-quote/handler/feeds.go` (#24); new config table = migration + model + `system.<table>.>` subject + `hst-core/handler/load.go` loader + subscribe list in nats.go:20-32.
4. Error/response contract: the single `HttpResponse` envelope, when to use `HttpResponseRetCode` vs `HttpResponseDenied`, which `errs.Err*` to pick, and that `HttpResponseStatus` exists (and its gaps, #1).
5. Env reference: every `config.go` constant with default and which module reads it; note the two meanings of "shard" (#17).
6. Logging/journal contract: `Log.Log(type, code, …)` with the MT5 type/code tables, when to write a journal entry vs a log line, and the actor/target keys.
7. Migration workflow: `make migrate-create name=…`, always a down file, keep model struct order = column order, run `make migrate-up` before `make run`; how to recover from a dirty version (`migrate-force`).
8. Health/readiness per service: hst-server `/api/v1/system/monitor/{health,live,cache,ws}` (no NATS check, #8); the other three serve probes on `HEALTH_PORT` with `DrainWait`.
9. The house rules that exist only in the skill file: one-line comments, `CrtX/UptX/ViewX`, `h.Go` not `go`, `make check` must be clean; a pre-commit hook or CI job would enforce them.
10. A test strategy page, since there are no tests to imitate (#7).
